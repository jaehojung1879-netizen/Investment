# US 현금 수익성 H63 — P4 탐색 실행 사전점검 (실행하지 않음)

연구 `us-cash-profitability-signal-v1`의 선행조건 P4(`P4_EXPLORATORY_FUTILITY_SCREEN`)를 **실행하기 전에**, 단 한 번의 역사적
탐색 실행이 동결된 프로토콜을 어기지 않고 가능한지 점검한 결과다. 이 변경은 아래를 하지 않았다.

- 결과를 읽지 않았다. 신호일 이후의 가격 값, 새 IC나 수익률, 새 forward label을 하나도 계산하지 않았다.
- 일회 탐색 예산을 쓰지 않았다.
- 소유자 승인 기록, 실행 워크플로, 잠금 ref를 만들지 않았다.
- 가설, 피처, H63 지평, 통제변수, 문턱값, 추론 방법을 바꾸지 않았다.

이 상태는 기록으로도 확인된다. 사전점검이 남긴 카운터는 `outcomeReads = 0`, `intervalComputations = 0`이고, 신호일 코호트 구성만
715회(`featureBuilds = 715`) 수행했다.

| 산출물 | 경로 |
|---|---|
| 하네스 (일회 실행 코드, 실행 안 함) | `pipeline/us_cash_profitability_exploratory.py`, `scripts/run_us_cash_profitability_exploratory.py` |
| 결과 비노출 사전점검 | `docs/us-readiness/us-cash-profitability-exploratory-preflight-v1.json` |
| 기계 판독 체크리스트 | `docs/us-readiness/us-cash-profitability-exploratory-readiness-v1.json` |

## 0. 결론 먼저

**질문: 기존 H63 현금 수익성 가설을 지금 역사적 미국 결과에 한 번 실행하면 동결된 연구 프로토콜을 어기는가?**

**지금 당장은 실행할 수 없다(BLOCKED).** 막는 것은 데이터나 방법이 아니다. 실행을 일회로 묶는 장치 두 개가 아직 없고, 둘 다
의도적으로 만들지 않았다.

1. 소유자 승인 기록이 없다.
2. 영속적인 일회 잠금(워크플로와 git ref)이 없다.

**과학적 준비도는 CONDITIONAL이다.**

- 동결된 정의는 그대로 재현된다. Phase 3의 55개 고정일 수치가 정확히 일치했다.
- 무결과 방화벽이 측정으로 확인됐다.
- 표본은 충분하다. 성숙하고 정의된 주간 코호트가 692개로, 260개 기준을 넘는다.
- 미해결 코호트는 0개다.

다만 아래 세 가지는 소유자가 **명시적으로 수용**해야 한다.

- 생존 편향: 이탈 종목 212개에 가격이 없다.
- 보정 기하 밖의 초기 연도: 정의된 날짜 163개(2013–2016에 집중)는 이름 수가 245 미만이다.
- 결과에 이미 노출된 역사: 이 실행은 무익성 선별일 뿐이다.

이 셋을 수용하면 두 장치를 만든 뒤 한 번 실행하는 것은 프로토콜 안에 있다. 그 결과는 **ABANDON(폐기) 또는 CONTINUE(전향
등록 검토로 진행)** 둘 중 하나일 뿐이다. **어떤 결과도 독립적 확증이 아니다.**

## 3. 하네스: 무엇을 재사용하고 무엇이 새로운가

재사용한 것(호출하며, 복사하지 않음):

- 구성원 분류: `us_capital_allocation_coverage.classify_member`. Phase 2/3와 같은 가격·식별 퍼널이며, 무거운 분배 엔진 없이 쓴다.
- 피처와 통제변수: `audit_us_alpha_phase3_readiness.row_values`.
- 가중치: `us_h63_inference_calibration.centred_ranks`, `residual_weights`.
- 구간: v4 `calendar_time_sn_interval`.

새로운 것(기계적인 부분만):

1. **복리 달력주 귀속.** 보정 연구는 균일한 5세션 주에서 가산 수익률을 시뮬레이션했다. 실제 코호트의 수익률은 비율이며,
   실제 달력주는 3–5세션이다. 코호트 수익률은 Σ_s (C[s]−C[s−1])/C[진입]으로 정확히 망원(telescope)된다. 그래서 각 세션의 기여를
   그 세션이 속한 ISO 주에 귀속시키고, 노출은 활성 코호트 수 / 63으로 둔다.
   - 가산 모드에서 v4 `calendar_time_series`와 **정확히 같다**(테스트).
   - 불규칙한 주에서도 Σ D = Σ S_t가 항상 성립하며, 성립하지 않으면 예외를 던진다.
2. **결과 방화벽.**
   - 신호일 이후 종가는 `read_outcomes`로만 얻는다.
   - 이 함수는 `OutcomePermit`이 없으면 거부한다.
   - 허가는 `authorize`만 발급하며, 소유자 승인 기록이 **모든 입력 식별자와 하네스 코드 해시**를 정확히 고정했을 때만 발급한다.
   - 결과 읽기 카운터는 호출 지점에서 증가한다. 그래서 "결과를 읽지 않았다"는 주장 대신 측정된 사실로 남는다.
3. **로컬 일회 가드.** 커밋된 결과(`docs/us-readiness/us-cash-profitability-exploratory-result-v1.json`)가 있으면 거부하고, 출력
   경로는 `docs/` 밖의 새 경로여야 한다. 이 두 검사는 모두 데이터를 읽기 **전에** 수행한다.

## 5. 실행이 승인되면 정확히 무엇이 일어나는가

1. 식별자를 검증하고 승인 기록과 대조한다. 하나라도 다르면 결과를 읽기 전에 중단한다.
2. 715개 주간 신호일의 코호트를 신호일 정보만으로 구성한다. 사전점검과 같은 코드다.
3. 성숙하고 정의된 코호트(현재 692개)의 보유 종목에 대해, 진입부터 2026-09-14까지의 총수익 종가를 **한 번** 읽는다.
4. 진입 또는 청산 종가가 없는 코호트를 UNRESOLVED로 표시한다. 그 비율이 10%를 넘으면 NOT_EVALUABLE이다.
5. 복리 달력주 계열을 만들고 CT_SN 단측 95% 경계를 계산한다.
6. 판정은 다음 규칙 하나뿐이다. 상한 ≤ 0이면 `ABANDON_BEFORE_PROSPECTIVE_COLLECTION`, 그 밖에는
   `CONTINUE_TO_PROSPECTIVE_REGISTRATION_REVIEW`. 하한 > 0이어도 "개발 표본에서 지지됨"으로만 기록한다. 이는 확증이 아니고,
   승격·생산 반영·투자 결정 근거가 될 수 없다.
7. 재실행, 재시드, 문턱·피처·지평 변경은 없다.
