# 한국 유니버스 히스토리: 어디서 오고, 무엇을 증명했고, 무엇을 아직 안 하는가

## 문제

리플레이 13년 내내 한국은 **생존자 편향 그대로**였다. `data/universe-history.json`에
KR 행이 한 줄도 없었고, 그래서 `pit_data.UniverseHistory.snapshot`은 한국을
"멤버십 불명"으로 읽어 **오늘의 종목을 2013년 단면에 그대로** 넣었다.

측정된 결과:

| 지표 | 값 |
|---|---|
| KR `membershipCoveragePct` | **0.0** |
| `survivorshipRisk` | HIGH |
| replay-v15 `survivorshipBound` | `REVERSES_UNDER_MEASURED_GAP` |
| 감사 표본 내 KR 비중 | 챔피언 14.4% / 챌린저 77.9% |

마지막 줄이 핵심이다. v15에서 유일하게 검정력 있는 측정(쌍체 블록 검정, CI
[−0.925, −0.119])의 역전은 **KR을 100%로 스트레스한 결과**였고, KR이 100%로
스트레스되는 이유는 멤버십 파일이 존재하지 않기 때문이었다.

## 왜 그동안 안 채웠나 — 두 번의 실패

`build_universe_history.kr_membership_is_not_available()`에 그대로 남아 있다.

1. **`KRX-DELISTING` 전체.** 그건 "KRX에서 상장폐지된 적이 있는 모든 이름"이지
   "투자 가능 유니버스의 구성종목이었던 이름"이 아니다. 1998년 코스닥 껍데기
   회사는 대형주 119개를 담는 장부의 전 구성종목이 아니다.
2. **오늘의 상장종목에 `listed: None`.** 하한이 없다는 뜻이고, 2020년에 상장한
   회사를 2013년 단면에 넣는다. 생존자 편향 수정이 아니라 **룩어헤드**다.

둘 다 **KNOWN 멤버십으로 읽혔다.** 그래서 파일은 자기가 지어낸 한국 단면에 대해
`membershipCoveragePct` 100%와 `survivorshipRisk` LOW를 보고했다. 아무도 못 잡은
이유는 Yahoo가 그 티커를 거의 서빙하지 않았기 때문이다(첫 실제 실행에서
3,010개 중 17개). **정합성이 벤더의 실패에 기대고 있었다.**

## 무엇이 달라졌나 — Probes run #4

KRX Open API `sto/stk_bydd_trd` (유가증권 일별매매정보), 구독된 키로 측정:

```
verdict: POINT_IN_TIME            (POINT_IN_TIME_SHORT_OF_REQUESTED_REACH 아님)

2013-01-02 vs 2026-09-01   겹침 77.42% · 떠남 210종목 · 편입 223종목
2013-01-02   930종목   리플레이 KR 유니버스 51/68 (75.0%) — 17개 나중 상장, 0개 결손
2016-01-04   887종목   54/68 (79.41%) — 14개 나중 상장, 0개 결손
2020-01-02   916종목   63/68 (92.65%) —  5개 나중 상장, 0개 결손
2026-09-01   943종목   68/68 (100.0%)

컬럼: ACC_TRDVAL ACC_TRDVOL BAS_DD CMPPREVDD_PRC FLUC_RT ISU_CD ISU_NM
      LIST_SHRS MKTCAP MKT_NM SECT_TP_NM TDD_CLSPRC TDD_HGPRC TDD_LWPRC TDD_OPNPRC
```

결정적인 두 가지는 **겹침이 100% 미만**이라는 것과 **떠난 종목이 실제로
나온다**는 것이다. 날짜 파라미터를 조용히 무시하는 엔드포인트는 2013년 요청에
오늘의 목록을 돌려주면서 모든 개수·형식 검사를 통과한다 — 겹침 100%가 그 서명이고,
여기서는 77.42%였다.

구독되지 않은 것들(전부 `Unauthorized API Call`): `sto/ksq_bydd_trd`(코스닥 —
유니버스가 100% `.KS`라 불필요), `sto/stk_isu_base_info`, `idx/kosdaq_dd_trd`.
`idx/kospi_dd_trd`와 `idx/krx_dd_trd`는 응답했지만 **0종목** — 지수 레벨이라
구성종목을 싣지 않는다.

## 규칙: 근사가 아니라 유니버스 자신의 규칙

`pipeline/universe._kr_kospi`는 KOSPI 상장목록을 시가총액으로 정렬해
`head(universe_size)`를 취한다. 재구성은 **같은 연산을 옛 날짜에 적용**한다.

```
members(D) = (D에서 시가총액 상위 universe_size)
             ∪
             (오늘 설정된 KR 종목 중 D에 실제로 거래된 것)
```

두 번째 항이 없으면 규칙이 **종목을 지운다.** `snapshot`은 행이 상장폐지라고
말하는 티커를 버리므로, 오늘의 설정 종목 중 상위 N 밖에 있는 것(예: 보통주의
일부 시총으로 거래되는 우선주)은 상장폐지 날짜를 받고 **살아있는 단면에서
사라진다.** 실제로 매매하는 유니버스를 줄이는 건 생존자 편향 수정이 아니라
반대 방향의 두 번째 편향이다.

두 항 모두 **거래된 것에 갇혀 있다.** D의 응답에 없는 종목은 어느 쪽이 주장하든
D의 구성종목이 아니다 — 이것이 두 번째 실패(룩어헤드)를 막는다.

## 오차의 방향과 크기

| | 값 | 방향 |
|---|---|---|
| 스냅샷 간격 | 월 1회 (165일) | — |
| `listed` 오차 | 실제 편입일 **이후** | 안전 — 종목을 실제보다 일찍 넣지 않음 |
| `delisted` 오차 | 최대 한 달 **늦음** | 떠난 종목을 조금 오래 들고 있음 |
| 비교: 미국 쪽 | 커밋 간격 최대 7개월 | 같은 방향, 더 큼 |

간격이 곧 상장폐지 쪽 오차의 상한이다. `--frequency weekly`가 있지만 기본값은
월간이다 — 165콜이면 백필 전체가 한 번의 실행에 들어간다.

## 정책이 어디에 사는가

수집기는 KRX가 말한 것만 쓴다 — 코드·이름·시가총액·상장주식수·그날의 시총 순위.
**유니버스 규칙은 적용하지 않는다.** 수집된 아티팩트에 구워 넣은 규칙은 다시
수집하지 않고는 바꿀 수 없기 때문이다. 규칙은 `krx_universe.members_on_date`에
있고, 따라서 다른 규칙은 재수집이 아니라 재유도다.

`--top`은 유니버스 크기가 아니라 순위의 천장이다. 한국 유니버스 68개에 대해
300은 어떤 확장에도 여유가 있고, 10년치 월간 단면을 원장에 들고 다닐 만큼 작다.
done-set은 각 날짜가 **어느 깊이로** 수집됐는지 기록하므로, `--top`을 올리면 더
얕게 수집된 날짜만 다시 묻는다 — 두 깊이를 이어 붙인 10년치 순위는 하나의
순위가 아니다.

## 봉인: 이 브랜치는 v15를 유지한다

한국 멤버십 행은 **한국 횡단면을 재정의한다.** `historical_replay`는 지역별로
`alpha_pct`를 계산하므로(`historical_replay.py:562`), 한국 기록의
`alphaPercentile`은 한국 종목들 사이의 순위다. 멤버십이 없는 동안 그 순위는
생존자 전용 집합에 대해 매겨졌고, 행을 쓰는 순간 떠난 210종목이 돌아와 **다른
회사 집합**에 대해 매겨진다.

`universe_conflict`는 이걸 거절하지 않고 있었다 — 전역 `mode`는 파일이
비어있다가 차는 순간에만 뒤집히는데 파일은 이미 미국 때문에 비어있지 않았고,
개수 비교 루프는 기록된 항목이 없는 지역을 아무것과도 비교하지 않는다. 기존
테스트가 이를 의도적으로 허용하고 있었고(`"오직 바뀐 지역만 횡단면이
재정의된다"`), 그 근거의 절반은 맞다 — 미국 기록은 안전하다. **빠진 것은 바뀐
지역 자신의 기록이다.** 이번에 고쳤다.

그래서 순서가 정해진다:

| | 봉인 | 재취득 |
|---|---|---|
| 이 브랜치 — 수집기 + 빌더 플래그 + 가드 수정 | **v15 유지** | 없음 |
| 수집 실행 (`Collect universe history`) | v15 유지 | 없음 |
| `replay.yml`에 `--krx-snapshots` 배선 | **v16 필요** | 50분 |

`replay.yml`은 아직 그 플래그를 넘기지 않는다. 수집기는 **아무도 읽지 않는
샤드**를 쓴다 — 의도적이다. 배선은 `REPLAY_VERSION` 상향과 같은 커밋에 있어야
하고, 그래야 새 세대가 야간 실행 중의 사고가 아니라 결정이 된다.
`test_reading_the_korean_shards_and_keeping_replay_v15_cannot_both_be_true`가
양방향으로 그걸 강제한다.

## 이것이 사지 않는 것

녹색 정합성 게이트가 아니다. `universe_ready`는 두 커버리지 모두 정확히 100.0을
요구하고 무료 벤더로는 어느 쪽도 닿지 않는다. 사는 것은 **한국의 구멍이
미지(unknown)에서 이름 붙은 회사들의 집합으로 바뀌는 것** — 편향 *한계(bound)*가
세워질 수 있는 유일한 토대다.
