# 한국 유니버스 히스토리: 어디서 오고, 무엇을 증명했고, 무엇을 아직 안 하는가

## 문제

리플레이 13년 내내 한국은 **생존자 편향 그대로**였다. `data/universe-history.json`에
KR 행이 한 줄도 없었고, 그래서 `pit_data.UniverseHistory.snapshot`은 한국을
"멤버십 불명"으로 읽어 **오늘의 종목을 2013년 단면에 그대로** 넣었다.

측정된 결과:

| 지표 | 값 |
|---|---|
| KR `membershipCoveragePct` | **0.0** |
| `survivorshipRisk` | HIGH |
| replay-v15 `survivorshipBound` | `REVERSES_UNDER_MEASURED_GAP` |
| 감사 표본 내 KR 비중 | 챔피언 14.4% / 챌린저 77.9% |

마지막 줄이 핵심이다. v15에서 유일하게 검정력 있는 측정(쌍체 블록 검정, CI
[−0.925, −0.119])의 역전은 **KR을 100%로 스트레스한 결과**였고, KR이 100%로
스트레스되는 이유는 멤버십 파일이 존재하지 않기 때문이었다.

## 왜 그동안 안 채웠나 — 두 번의 실패

`build_universe_history.kr_membership_is_not_available()`에 그대로 남아 있다.

1. **`KRX-DELISTING` 전체.** 그건 "KRX에서 상장폐지된 적이 있는 모든 이름"이지
   "투자 가능 유니버스의 구성종목이었던 이름"이 아니다. 1998년 코스닥 껍데기
   회사는 대형주 119개를 담는 장부의 전 구성종목이 아니다.
2. **오늘의 상장종목에 `listed: None`.** 하한이 없다는 뜻이고, 2020년에 상장한
   회사를 2013년 단면에 넣는다. 생존자 편향 수정이 아니라 **룩어헤드**다.

둘 다 **KNOWN 멤버십으로 읽혔다.** 그래서 파일은 자기가 지어낸 한국 단면에 대해
`membershipCoveragePct` 100%와 `survivorshipRisk` LOW를 보고했다. 아무도 못 잡은
이유는 Yahoo가 그 티커를 거의 서빙하지 않았기 때문이다(첫 실제 실행에서
3,010개 중 17개). **정합성이 벤더의 실패에 기대고 있었다.**

## 무엇이 달라졌나 — Probes run #4

KRX Open API `sto/stk_bydd_trd` (유가증권 일별매매정보), 구독된 키로 측정:

```
2013-01-02   930종목   리플레이 KR 유니버스 51/68 (75.0%) — 17개 나중 상장, 0개 결손

      LIST_SHRS MKTCAP MKT_NM SECT_TP_NM TDD_CLSPRC TDD_HGPRC TDD_LWPRC TDD_OPNPRC
```

결정적인 두 가지는 **겹침이 100% 미만**이라는 것과 **떠난 종목이 실제로
나온다**는 것이다. 날짜 파라미터를 조용히 무시하는 엔드포인트는 2013년 요청에
오늘의 목록을 돌려주면서 모든 개수·형식 검사를 통과한다 — 겹침 100%가 그 서명이고,
여기서는 77.42%였다.

구독되지 않은 것들(전부 `Unauthorized API Call`): `sto/ksq_bydd_trd`(코스닥 —
유니버스가 100% `.KS`라 불필요), `sto/stk_isu_base_info`, `idx/kosdaq_dd_trd`.
`idx/kospi_dd_trd`와 `idx/krx_dd_trd`는 응답했지만 **0종목** — 지수 레벨이라
구성종목을 싣지 않는다.

## 규칙: 근사가 아니라 유니버스 자신의 규칙

`pipeline/universe._kr_kospi`는 KOSPI 상장목록을 시가총액으로 정렬해
`head(universe_size)`를 취한다. 재구성은 **같은 연산을 옛 날짜에 적용**한다.

```
members(D) = (D에서 시가총액 상위 universe_size)
             ∪
             (오늘 설정된 KR 종목 중 D에 실제로 거래된 것)
```

두 번째 항이 없으면 규칙이 **종목을 지운다.** `snapshot`은 행이 상장폐지라고
말하는 티커를 버리므로, 오늘의 설정 종목 중 상위 N 밖에 있는 것(예: 보통주의
일부 시총으로 거래되는 우선주)은 상장폐지 날짜를 받고 **살아있는 단면에서
사라진다.** 실제로 매매하는 유니버스를 줄이는 건 생존자 편향 수정이 아니라
반대 방향의 두 번째 편향이다.

두 항 모두 **거래된 것에 갇혀 있다.** D의 응답에 없는 종목은 어느 쪽이 주장하든
D의 구성종목이 아니다 — 이것이 두 번째 실패(룩어헤드)를 막는다.

## 오차의 방향과 크기

| | 값 | 방향 |
|---|---|---|
| 스냅샷 간격 | 월 1회 (165일) | — |
| `listed` 오차 | 실제 편입일 **이후** | 안전 — 종목을 실제보다 일찍 넣지 않음 |
| `delisted` 오차 | 최대 한 달 **늦음** | 떠난 종목을 조금 오래 들고 있음 |
| 비교: 미국 쪽 | 커밋 간격 최대 7개월 | 같은 방향, 더 큼 |

간격이 곧 상장폐지 쪽 오차의 상한이다. `--frequency weekly`가 있지만 기본값은
월간이다 — 165콜이면 백필 전체가 한 번의 실행에 들어간다.

## 정책이 어디에 사는가

수집기는 KRX가 말한 것만 쓴다 — 코드·이름·시가총액·상장주식수·그날의 시총 순위.
**유니버스 규칙은 적용하지 않는다.** 수집된 아티팩트에 구워 넣은 규칙은 다시
수집하지 않고는 바꿀 수 없기 때문이다. 규칙은 `krx_universe.members_on_date`에
있고, 따라서 다른 규칙은 재수집이 아니라 재유도다.

`--top`은 유니버스 크기가 아니라 순위의 천장이다. 한국 유니버스 68개에 대해
300은 어떤 확장에도 여유가 있고, 10년치 월간 단면을 원장에 들고 다닐 만큼 작다.
done-set은 각 날짜가 **어느 깊이로** 수집됐는지 기록하므로, `--top`을 올리면 더
얕게 수집된 날짜만 다시 묻는다 — 두 깊이를 이어 붙인 10년치 순위는 하나의
순위가 아니다.

## 봉인: 이 브랜치는 v15를 유지한다

한국 멤버십 행은 **한국 횡단면을 재정의한다.** `historical_replay`는 지역별로
`alpha_pct`를 계산하므로(`historical_replay.py:562`), 한국 기록의
`alphaPercentile`은 한국 종목들 사이의 순위다. 멤버십이 없는 동안 그 순위는
생존자 전용 집합에 대해 매겨졌고, 행을 쓰는 순간 떠난 210종목이 돌아와 **다른
회사 집합**에 대해 매겨진다.

`universe_conflict`는 이걸 거절하지 않고 있었다 — 전역 `mode`는 파일이
비어있다가 차는 순간에만 뒤집히는데 파일은 이미 미국 때문에 비어있지 않았고,
개수 비교 루프는 기록된 항목이 없는 지역을 아무것과도 비교하지 않는다. 기존
테스트가 이를 의도적으로 허용하고 있었고(`"오직 바뀐 지역만 횡단면이
재정의된다"`), 그 근거의 절반은 맞다 — 미국 기록은 안전하다. **빠진 것은 바뀐
지역 자신의 기록이다.** 이번에 고쳤다.

그래서 순서가 정해진다:

| | 봉인 | 재취득 |
|---|---|---|
| 이 브랜치 — 수집기 + 빌더 플래그 + 가드 수정 | **v15 유지** | 없음 |
| 수집 실행 (`Collect universe history`) | v15 유지 | 없음 |
| `replay.yml`에 `--krx-snapshots` 배선 | **v16 필요** | 50분 |

`replay.yml`은 아직 그 플래그를 넘기지 않는다. 수집기는 **아무도 읽지 않는
샤드**를 쓴다 — 의도적이다. 배선은 `REPLAY_VERSION` 상향과 같은 커밋에 있어야
하고, 그래야 새 세대가 야간 실행 중의 사고가 아니라 결정이 된다.
`test_reading_the_korean_shards_and_keeping_replay_v15_cannot_both_be_true`가
양방향으로 그걸 강제한다.

## 이것이 사지 않는 것

이 글을 쓴 시점엔 녹색 정합성 게이트가 아니었다. `universe_ready`는 그때 두
커버리지 모두 정확히 100.0을 요구했고 무료 벤더로는 어느 쪽도 닿지 않았다. 이때
산 것은 **한국의 구멍이 미지(unknown)에서 이름 붙은 회사들의 집합으로 바뀌는 것**
— 편향 *한계(bound)*가 세워질 수 있는 유일한 토대였다.

**(2026-09-17 갱신)** 그 한계가 실제로 세워진 뒤, 게이트 자체가 100.0 요구에서
20% 허용 임계값으로 바뀌었다 — 이 문서가 만든 토대(한국 구멍의 실측) 위에서
`survivorshipBound`가 갭 전체에서도 결론을 안 뒤집는다는 게 확인됐기 때문이다.
근거는 README와 `docs/us-delisted-prices-source.md` 참고.

## 왜 멤버십만으로는 부족한가

`unvouched`는 **합집합**이다 (`pit_data.py:731`):

```
unvouched = (상장됐는데 가격을 못 붙인 것)  ∪  (멤버십 불명)
```

| 날짜 | 횡단면 | 이후 이탈 | 비중 |
|---|---|---|---|
| 2013-01-02 | 121 | 46 | **38.0%** |
| 2015-01-02 | 135 | 55 | **40.7%** |
| 2017-01-02 | 145 | 59 | **40.7%** |
| 2021-01-04 | 149 | 50 | 33.6% |
| 2025-01-02 | 139 | 24 | 17.3% |

한국 가격은 FinanceDataReader가 서빙하고, 이 저장소가 측정한 **상장폐지 종목 커버리지는 34.55%**다. 멤버십만 배선하면 KR `unvouched`는 100% → **약 25%**에서 멈춘다. 4배 개선이지만 0이 아니고, v15의 역전은 KR을 100%로 스트레스한 결과였으므로 한 세대를 쓰고도 답이 안 나올 수 있다.

## 같은 엔드포인트가 가격을 싣고 온다

Probes run #4가 기록한 컬럼에 이미 있었다:

```
TDD_OPNPRC · TDD_HGPRC · TDD_LWPRC · TDD_CLSPRC · ACC_TRDVOL · LIST_SHRS
```

`sto/stk_bydd_trd`는 **그날 거래된 것**을 나열한다 — 2014년에 상장폐지된 종목은 2013년 응답에 다른 종목과 똑같이 들어 있다. 커버리지가 34.55%가 아니라 **실제로 손바뀜한 전부**다.

## 기저(basis) — 유일하게 미묘한 부분

`price_adjustment.to_total_return`은 **분할조정·배당미조정** 프레임을 받아, 각 세션에 *이후* 분할의 곱을 곱해서 실거래가를 복원한다. KRX는 **이미 실거래가**다. 그대로 넘기면 아무도 안 한 조정을 되돌린다.

그래서 `krx_prices.to_vendor_basis`가 **반대로** 간다 — 같은 future-split 계수로 나눠서 FDR이 발행했을 모양을 만들고, 검증된 보정 경로가 한 줄도 안 바뀐 채 돌아간다. 왕복이 정확하다:

```
삼성전자 2018-05-04 1:50 액면분할
  as-traded 2,650,000 → vendor basis 53,000 → to_total_return 2,650,000  (정확)
  분할일 수익률:  보정 없이 −98.0000%  →  이 경로 통과 후 +0.0000%
```

`test_the_round_trip_returns_the_printed_prices_exactly`가 이걸 고정한다. 놓친 분할은 **예외를 내지 않고 잘못돼 보이지도 않으며**, 한 종목의 10년 이력이 50배 부풀어 "굉장한 모멘텀"으로 읽힌다 — 봉인되고 나면 발견은 운에 맡겨진다.

## 분할은 어디서 오나

이 엔드포인트에 이벤트 피드는 없다. `LIST_SHRS`가 모든 행에 있고, 액면분할은 **주식수를 k배 하면서 가격을 k로 나누는** 유일한 행위다 — 시가총액이 보존된다. 유상증자도 `LIST_SHRS`를 올리지만 **가격을 나누지 않는다.** 그래서 두 움직임이 **서로를 입증할 것**을 요구하면 갈라진다. 주식수만 움직이면 분할이 아니라고 기록한다.

## KRX가 안 싣는 것 — 명시

**배당.** 여기서 온 종목의 지수는 총수익이 아니라 **가격수익**이다. 떠난 종목의 성과를 배당수익률만큼 과소평가한다 — 생존편향 보정 목적에는 이탈 종목을 실제보다 **나쁘게** 보이게 하므로 보수적인 방향이지만, 반올림 오차가 아니라 실제 한계다.

## 비용과 용량

| | 값 |
|---|---|
| 호출 | 주중 하루 1회, 2013-01-01 ~ 오늘 ≈ **3,570콜** |
| 시간 | 기본 간격 0.4s 기준 ≈ **24분** |

수집기가 적용하는 유일한 결정은 **어떤 티커를 남길지**이고, 이건 판단이 아니라 **용량 상한**이다. 엔드포인트는 거래소 전체(약 930종목)를 돌려주고, 그걸 10년치 일별로 쌓으면 수백 MB다. 멤버십 샤드가 횡단면에 들어올 수 있는 유일한 티커들을 이름 대고 있으니 그것만 남긴다. `--all-issues`로 필터를 끌 수 있고, **호출 수는 어느 쪽이든 같다.**

## 봉인 — 이 브랜치도 v15를 유지한다

`replay.yml`은 `--krx-snapshots`도 `ledger/prices/kr`도 넘기지 않는다. 두 수집기 모두 **아무도 읽지 않는 샤드**를 쓴다.

`test_no_kr_point_in_time_input_is_wired_while_replay_v15_stands`가 양쪽을 한 불변식으로 묶는다 — 멤버십이든 시세든 `replay.yml`에 배선되는 순간 `REPLAY_VERSION`이 v15가 아니어야 한다. 한국 기록의 `alphaPercentile`은 한국 종목들 사이의 순위이고(`historical_replay.py:562`), 멤버십은 어떤 이름이 횡단면에 있는지를, 시세는 그 중 어떤 이름에 값을 매길 수 있는지를 바꾼다. 둘 다 같은 것을 재정의한다.

## 실행 순서

1. **Collect universe history** → `what: membership` — 완료 (run #2)
2. **Collect universe history** → `what: prices` — 3,570콜, 약 24분

4. 배선 + `REPLAY_VERSION` → **v16** (50분 재취득, **한 번만**)

# 3부: 감사가 잡은 것 — 수집은 맞았고, 보정이 틀렸다

## run #3 (2026-09-15)

```
3,364세션 · 1,722,439행 · 624종목 · 2013-01-02 .. 2026-09-14 · 남은 0일 · 49MB
```

수집기는 완주했다. 감사 장치가 **보정 쪽 결함 세 개**를 잡았고, 그게 감사를 넣은 이유다. 첫 출력:

```
검출된 분할 302건
  2013-01-10  017800.KS  액면분할 x1.12113     ← 분할 비율이 아니다
일일 제한(30%) 초과 잔여 변동: 345건
  2013-02-15  001260.KS  +3300.00%            ← 정확히 ×34
  2017-03-30  071970.KS  +1900.00%            ← 정확히 ×20
```

정확히 떨어지는 숫자는 시장이 만들지 않는다.

## 결함 1 — 거래정지 봉이 세션으로 들어갔다

```
071970.KS   2017-03-24 ~ 04-04   8세션 연속 volume 0
            종가 2,765 고정 → 55,300 고정
```

KRX는 거래정지 종목의 **마지막 종가를 그대로 실어 나른다.** 그 행을 세션으로 읽으면 가짜 평탄봉이 패널에 들어가고, 정지 구간 전체가 한 세션 수익률로 찍힌다. `parse_bars`에 "종가 없는 행은 세션이 아니다"는 넣었으면서 **거래량에는 같은 규칙을 안 넣은 것**이 원인이다.

→ `frame_from_rows`가 `volume == 0`을 버린다. **유도 시점**에 버리므로 저장된 행은 남고, 정지 자체가 그 종목에 대한 사실로 보존된다. 전체의 1.0%(17,511행).

## 결함 2 — 상대 허용오차가 증자를 전부 통과시켰다

```
017800.KS  2013-01-10   주식수 +12.1%   가격 +2.2%   → x1.12113로 기록
```

주식수비 1.12 주위의 **상대** 20% 허용오차는 "가격이 전혀 안 움직임"을 포함한다. 그래서 5분의 1 미만의 모든 증자가 분할로 기록되고, 그 이전 모든 세션이 1.12로 나뉘었다.

놓친 원리: **분할 비율은 액면가 비율이다.** 5,000→500은 10배, 5,000→100은 50배. 정수이거나 1/정수이고, 1.12113은 될 수 없다.

→ 후보는 **가격비가 깨끗한 비율에 앉는 세션**. 가장 작은 깨끗한 비율이 2이므로 후보가 되려면 한 세션에 **42.5% 이상** 움직여야 하고, 일일 제한 안에서는 불가능하다. **후보는 이미 전부 기업행위**이고, 주식수는 *어느* 행위인지만 말한다.

## 결함 3 — 주식수는 권리락보다 몇 주 늦는다

```
064960.KS (SNT모티브)
  2025-01-24   종가 51,000 → 25,500 (정확히 ½)   주식수 변화 없음
  2025-02-26   종가 변화 없음                     주식수 14,623,136 → 26,540,272
                                                 ← 33일 뒤, 그리고 ×1.815 (×2 아님)
```

`LIST_SHRS`는 **신주가 형식적으로 상장되는 날** 갱신되는 등기 수치다. 같은 날 입증은 구조적으로 이걸 볼 수 없고, 그래서 첫 버전이 150종목을 잘못 거부했다. 배수도 정확히 2가 아니다 — 같은 창에서 증자가 함께 결제됐다.

→ 창 **75일** 안에서, 주식수가 **가격이 함의하는 비율 쪽으로** 움직였는지 본다(그 비율에 정확히 앉을 것이 아니라, 1보다 그쪽에 가까울 것). 방향성이 인적분할과 분할을 가른다:

```
267260.KS  2018-11-23  가격 정확히 −50%, 주식수 영구 불변  → 인적분할, 분할 아님
```

## 거부해선 안 되는 세 가지 — 전부 진짜 수익률

| | 왜 진짜인가 |
|---|---|
| 정지 건너뛴 구간 | 간격이 몇 달. 하루치가 아니라 **누적** 수익률 |
| **정리매매** | 상장폐지 직전 ~2주, **가격제한폭이 없어진다.** 한진해운이 여기서 −68% |
| 제한폭 이내 | 제한폭이 있는 이유 |

정리매매를 버리면 **찾으려던 생존편향 신호 자체를 지운다.** `unexplained_moves`가 위치로 분류하고, `detect_splits`는 그 구간에서 아무것도 기록하지 않는다.

## 설명 안 되는 것은 거부한다

감자·재상장·정지 중 기준가 재설정은 `LIST_SHRS`가 기술하지 않고 이 엔드포인트에 피드가 없다. **지어낸 +3,300%가 모멘텀 신호에 들어가는 것보다 이름 붙은 구멍이 낫다.** `panel_from_rows`가 그 종목을 빼고, 감사가 이름과 날짜로 센다.

## 재수집은 없었다

수집기가 **정책 없이 KRX 원본만 저장**했기 때문에 이 세 수정은 전부 **재유도**였다. 3,570콜을 다시 쓰지 않았다. "수집 아티팩트에 구워 넣은 규칙은 재수집 없이 못 바꾼다"는 설계 원칙이 처음으로 값을 한 지점이다.

# 4부: 배선 — replay-v16

## 무엇이 바뀌었나

| | |
|---|---|
| `replay.yml` | `build_universe_history --krx-snapshots ledger/universe/kr` · `run_replay --krx-prices ledger/prices/kr` |
| `korea_prices.acquire` | `fallback=` — **1차 벤더가 아무것도 못 준 종목만** 채운다 |
| `provenance` | `REPLAY_VERSION` → **replay-v16** · `DATA_VERSION += krx-pit-universe-and-prices-kr-v1` |

## 이음매 — 왜 여기인가

`acquire()`는 이미 `session_fetcher`를 주입받고, 이미 규칙 하나를 지킨다:

> **한 종목은 한 벤더가 통째로 서빙하거나 아예 안 하거나.**

두 벤더의 세션을 한 종목 이력에 이어붙이면 한 시리즈에 두 가격 기저가 들어가고 **이음매가 수익률로 읽힌다.** KRX 폴백도 같은 규칙을 따른다 — 1차가 **아무것도** 못 준 종목만 채운다.

**짧은 이력은 구멍이 아니다.** replay-v12가 벤더의 capped window 때문에 v11보다 46,356행을 적게 봉인하고도 에러 하나 없었다. 그걸 판정하는 건 `coverage_shortfall`이고, 2차 소스로 조용히 메우면 **거부하도록 만든 것을 안 보이게 만든다.**

## 이벤트가 함께 따라간다

`to_total_return`은 프레임 자체 컬럼보다 **명시적 events를 우선**한다. 상장폐지된 한국 종목에 야후는 아무것도 없으므로, 야후 것만 넘기면 `detect_splits`가 찾은 분할이 **조용히 사라진다.**

| 폴백 종목의 events | |
|---|---|
| 분할 | 프레임 자신의 것 (`LIST_SHRS`에서 유도) |
| 배당 | 야후가 그 종목을 들고 있으면 야후 것 |
| 야후의 분할 | **버린다** — 주식수가 이미 확정했고, 두 번 적용하면 2,500배가 된다 |

KRX는 배당을 안 실으므로 폴백 종목은 **가격수익** 기저다. 떠난 종목을 배당수익률만큼 과소평가하는데, 생존편향 보정에는 보수적 방향이고 숨기지 않고 적는다.

## 봉인 불변식

`DATA_VERSION`의 `krx-pit-universe-and-prices-kr-v1` 마커가 **두 저장소를 다** 주장한다. 테스트가 각각을 마커에 묶는다:

```
"--krx-snapshots" in replay.yml  ==  마커 있음
"--krx-prices"    in replay.yml  ==  마커 있음
마커 있음                        ==  REPLAY_VERSION != replay-v15
```

*"적어도 하나는 배선됨"* 식 테스트는 **시세 저장소가 조용히 빠져도 통과**하고, 열지도 않은 바를 읽었다고 주장하는 세대를 남긴다. 네 방향 전부 뮤테이션으로 확인했다.

## 왜 v15를 못 잇는가

`historical_replay`는 지역별로 `alpha_pct`를 계산한다(`:562`). 한국 기록의 `alphaPercentile`은 한국 종목들 사이의 순위이고, v15 내내 그 순위는 **생존자 전용 집합**에 대해 매겨졌다. 멤버십은 *어떤 이름이 횡단면에 있는지*를, 시세는 *그 중 어떤 이름에 값을 매길 수 있는지*를 바꾼다 — 둘 다 같은 것을 재정의한다.

v15의 기록은 봉인된 채 남고, v16은 새 전체 실험이며 그에 따르는 재취득을 치른다.
