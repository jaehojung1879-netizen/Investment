## 승인 전 차단해야 할 실행기 결함

원본 #316 파일을 수정하지 않고 정확한 코드 바이트의 순수 함수만 AST로 추출해 합성 재현했다.
`execute`/`main`과 실제 입력 로더는 이 감사 환경에 존재하지 않는다.

1. **BLOCKER — 미귀속 한도 미적용:** 100개 중 8개만 계산 가능한 음수 합성 표본도
   `SELECTION_NEGATIVE_AFTER_FIXED_EXPOSURE`가 나온다. 사양의 `>10%` 미귀속 시
   `SOURCE_OR_SAMPLE_INSUFFICIENT` 규칙을 positive/negative 판정보다 먼저 적용해야 한다.
2. **BLOCKER — Owner 커밋 확인 부재:** Git 저장소 밖의 추적되지 않은 자체 작성 파일도
   가짜 사양 식별자와 일치하는 코드 해시만으로 `authorization_ok`를 통과한다.
   원본 문서가 약속한 Owner 커밋 확인이 구현돼 있지 않다. author 문자열만 확인하는 것도 충분하지 않다.
3. **BLOCKER — 일회 실행 소비 보호 부재:** 원본 runner는 실행 소비 상태를 확인하지 않으며
   `--out`도 덮어쓸 수 있다. 기존 Phase C/D 잠금을 재사용·해제하지 않는 별도 C2 예외의
   승인 연결, 일회 소비/실패 상태 및 새 출력 파일 보존이 필요하다.
4. **결정 전 명확화:** 1배 비용에서의 95% 경계라는 판정 문구와 달리 현재 CI는 **gross**
   selection에서 계산된다. 비용을 바꿔도 CI는 같다. 2배 평균 조건만 net gap이다.
   gross 귀속 진단인지 net 선택효과 검정인지 결과 열람 전에 명확히 해야 한다.
   이번에는 사양·계산식·기준을 바꾸지 않았다.

`registered-code-audit.json`은 세 재현과 원래 합성 경제식 검사의 결과다.
이를 새로운 역사 C2 결과나 #316 자체의 승인으로 해석하지 않는다.

## 실제 코드와 재현

기존 #317 경제성 gate (`a3ee7a71…`)와 #320 ETF parser (`621fccb1…`)를 정확한 Git 객체에서
해시 검증 후 읽기 전용으로 호출한다. 귀속/비교 엔진은 복제하지 않았다.

  --repo . --raw-dir /path/to/retained/raw --out /tmp/c2-source-audit-new.json

해당 커밋 객체가 없는 clone은 #316/#317/#320과 위 ledger 커밋을 읽기 전용으로 가져와야 한다.

새 단위 검사 35건, 원래 #316 계산기/runner 합성 검사 21건이 통과했다.
