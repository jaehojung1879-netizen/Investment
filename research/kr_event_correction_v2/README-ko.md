# P2/K7 정정 실행 v2 — 네 셀만, 아직 실행하지 않음

이 폴더는 #327의 P2 H126/H252, K7 H126/H252를 정정 비교하기 위한 정확 해시 패킷이다. 새 가설·기간·임계값 탐색은 없다. 원래 결과·계약·claim·코드 10파일은 보존하고 새 입력 함수·영향받는 청산 루프만 버전 분리했다. 기본 명령은 검증이며 가격 샤드나 역사 수익률을 열지 않는다.

```bash
python -m research.kr_event_correction_v2.run
```

현재 결과는 `SOURCE_BLOCKED`, `pricesOpened=0`, `historicalExecutions=0`, `liveWrites=0`이다. `source-admission-v2.json`의 빈 항목은 실제 결측이며 가공한 허용값이 아니다. 코드가 존재한다고 정정 성과가 존재하는 것은 아니다.

**수정과 한계**

* `shareholder_inputs_v2.py`: 자회사 배당 제외, 확인된 COMMON 대상으로 common DPS만 사용, 별도 원본 충돌·모호한 정정·배당락일 충돌 차단. 누락 DPS와 실제0을 구별한다.
* 과거 베타는 신호 전 이용 가능했던 배당·기업행동 정보만 사용한다. 당시 알 수 없던 배당금/분할 확인을 나중 정보로 채우지 않고 셀을 차단한다. 주식수 스냅샷은 기준일과 접수일 중 이른 날짜보다 앞선 자료만 사용한다.
* 역사 K7 정정은 공식 회계연도 원천을 요구한다. 기준일 연도를 회계연도로 대체하지 않는다. 전향 기록의 안정적12-31 기준일 프록시와도 등급이 다르다.
* 인용 근거가 있는 split/reverse split/주식배당 비율 및 현금 종결대가는 처리한다. 동시 배당의 주식 단위, 권리·합병·분할 등의 경제적 패키지, 불완전 종결·기업행동은 차단한다. 주가 비율만으로 분할을 추정하지 않는다.
* `engine_v2.py`: 기존 beta/slot/비중/거래비용 함수는 재사용하고, 만기 때 정지한 잔존 종목을 최초 거래재개 종가에 청산하도록 루프만 버전 분리했다. 마지막 사건 뒤 정지 꼬리도 실제 청산까지 연장한다. 가격·종결대가가 없으면 차단하고 실제 전액 손실은 원금을 재생성하지 않는다.
* P2는 기존 제목상 발행 결정 집합이다. CB/EB/BW/유상증자의 실제 경제적 희석은 별도 증거 필드이며, 수익에 맞춰 사건을 빼거나 새로운 가설로 바꾸지 않는다.
* 정책금리 현금은 프록시, 비용은 모델, 투자자 세전이다. 수정 전후 모두 결과 노출 후 진단이고 독립 확증이나 LIVE 승격이 아니다.

**정확한 실행 범위와 출력**

네 셀의 126/252세션, 배당25%, 주식수0.9~1.1, 원래 Top300, 2026-10-30 cutoff, 원래 비용표·현금3가정·bootstrap9999/seed319320을 고정한다. 수정된 원천·사건·beta lineage와 비용1/2/3배 δ/CI, 비교 가능한 책·ETF 성과, 연도별 합계, 일별 경로와 청산 지연을 별도 결과에 남긴다. 비용0은 기존 비용 진단용이다. K7/H252를 새 확증 가설로 올리지 않는다.

포트폴리오는 완전한 **저장 원장**이 있을 때만 기존 경로/희석 신규진입 제외 후 차순위/제외분 ETF 세 경로를 같은 자본·비용으로 계산한다. 회피기간은 이미 고정된252세션이다. 차순위는 저장 순서를 사용하고 제외된 자본 슬롯을 승계하되 당시 종목·업종·개수 상한을 지키며 부족분은 ETF로 둔다. 기보유 종목의 강제 매도 규칙을 추가하지 않는다. 원래 C2의 일별 순수익을 비용별1e−9 이내에서 재현하지 못하면 비교를 차단한다. C2 계산기·피처·랭킹 재실행은 없다. 현재 그 원장이 없으므로 포트폴리오 비교는 미측정이다.

첫 포트폴리오 진입보다 앞선252세션의 희석 공시 이력도 필수다.
`signalCalendar`/`dilutionEventCoverageFrom`과 필요한 `priorP2Events`가 없으면
과거를 '사건 없음'으로 가정하지 않고 차단한다. 이 lead-in은 새 성과 표본이 아니다.
거래정지 중 배당락 재투자나 분할 뒤 가격을 추정하지 않으며 인용된 현금 종결대가만
거래 없이 인정한다. 총수익 지수의 배당락 재투자 관례는 실제 지급일 현금 장부가
아니므로 실제 배당 지급·자금조달 및 체결 경제의 qualification도 여전히 필요하다.

**다음 단계는 승인보다 원천 보완이 먼저다.** 공식 주식 종류/법인 매핑, 회계연도, 정정 연결, 기업행동·종결대가 및 전체 C2 원장을 확인해 admission을 채운 뒤 패킷을 다시 고정해야 한다. admission이 달라지면 해시와 승인을 새로 받아야 한다. 결측을 숨긴 채 현재 패킷 실행을 승인해 달라고 요청하지 않는다.

실행 런타임은 패킷에 명시된 Python·패키지 버전과 일치해야 한다. 별도
`requirements-v2.txt`가 있으며 기존 봉인 런타임은 바꾸지 않는다. 일반 CI의
metadata-only 검증은 설치되지 않은 실행 의존성을 결측으로 표시할 수 있다.

자료가 완비되고 정확한 신규 Owner 승인이 커밋됐을 때 사용할 명령만 준비했다:

```bash
python -m research.kr_event_correction_v2.run --mode execute \
  --prices /ABS/PINNED_SIGNAL_HISTORY/ledger/prices/kr \
  --universe /ABS/PINNED_SIGNAL_HISTORY/ledger/universe/kr
```

실행은 새로운 자체 claim과 비강제 원격 태그를 사용하며 기존 잠금을 재활성화·삭제하지 않는다. 잠금 뒤 실패는 소진이며 재시도하지 않는다. 현재 Owner 승인 파일·claim·결과·태그는 만들지 않았다.
