# 미국 CTVA 원종가 복구 — 전략 결과 해석 전 입력 정정

2026-11-18 KST. 원 설계 `e6786ee`의 신호·후보·ETF 비중·매칭 범위·검정 가족·판단 규칙을 유지한다. 이번 문서는 새 미국 전략 결과를 읽거나 후보를 고르기 전에 입력 오류의 근거와 정정을 고정한다. 한국 계산은 독립적으로 계속한다.

## 확인한 오류

새 Yahoo capture에서 CTVA의 과거 Close는 봉인된 가격과 기업행위로 복원한 당시 원종가의 약 `1/6.665`, Volume은 약 `6.665`배였다. 원 검증기는 수준 차이를 검사하지 않아 `VERIFIED`를 반환했다. 후보 수·CIK·검증 상태가 같다는 사실만으로 당시 시총·가치 점수가 같다고 볼 수 없다.

원 fetch URL의 고정 종료일은 2026-09-09여서 그 이후 기업행위를 받지 못했다. 입력만을 확인하는 별도 Yahoo 응답은 **2026-10-01 13:30 UTC, splitRatio `6665:1000`**을 반환했다. 해당 응답의 SHA-256은 `c8f9f48f042a7d9c9843ee7777c73d26852987880c9c30aad910966f99956fa5`다. 정확한 원문·URL·관측시각은 저장소 밖 `/workspace/batch-inputs/us/ctva-postcutoff-event-probe.response.json.gz`와 `.receipt.json`에 보존한다. 이 배율은 과거 Close와 Volume의 차이를 설명한다.

## 고정한 복구 방법

1. 이미 캡처한 HTTP 원문은 바꾸지 않는다. 정정 전 parsed capture·features/meta·진행 로그·생성된 결과가 있으면 별도 archive와 SHA로 보존한다. 중단된 계산을 완성된 성과로 표시하지 않는다.
2. parsed CTVA 입력에 위 응답에서 확인한 분할 event 하나와 그 source receipt만 추가한다. 원 `AsTraded.close_on`의 **해당 판단일 이후 분할을 되돌리는 처리**가 당시 원종가를 복구하도록 한다. 실제 분할일은 연구 판단일 범위 이후이므로 당시 정보에 미래 분할 신호를 추가하는 규칙이 아니다.
3. 봉인 가격 역산 값을 feature 가격이나 시총에 덮어쓰지 않는다. 원 AsTraded 검증·admission·회계 필드·점수·업종 cap과 모든 구성은 유지한다. 원 생성기로 features를 다시 만든다.
4. 같은 원종가·거래량 기준 감사를 전체 ticker에 다시 적용한다. 정정 전후 feature hash·CTVA 입력 변화·유니버스/CIK 통계와 기존 published 기준 수치 차이를 모두 보고한다. 기존 결과의 입력 오류가 확인되면 원 집계를 지우거나 이번 정정 결과와 동일하다고 부르지 않는다.

추가 입력 정정이 필요하면 원천 증거와 범위를 다시 기록한다. 성과 개선 여부는 입력 정정의 채택 기준으로 사용하지 않는다. 새 capture의 빈티지 차이·공시 가시성 한계는 그대로 남는다.
