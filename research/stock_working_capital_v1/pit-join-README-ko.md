## 원천이 실제로 증명한 것과 차단한 것

**모집단:** 저장된 KRX 원천은 매월 첫 거래일의 Top300 순위다. 신호일 종가 기준으로 이용 가능한 최근
스냅샷의 **정확한 1~120위**를 연결했다. 이는 당일 시장 전체를 다시 순위 매긴 Top120이 아니다.
미래 스냅샷·121위 대체·현재 생존 종목 집합을 쓰지 않는다. 기준 스냅샷 날짜, 경과일과 membership basis를 남긴다.
2017년 10월 스냅샷이 없어 10/13·10/20·10/27의 **360행은 stale**로 차단했다. 9월 이름을 조용히 정상화하지 않았다.

**공시 vintage:** 보존된 DART 원문 **2,533건**의 archive/body SHA, 최초 비정정 listing metadata,
main 제목·접수번호·corpCode·stock code·보고기간 월을 검사했다. 양쪽 접수번호/main이 맞는 member-date는 14,511행이다.
현재 raw 재무 API 접수번호가 보존된 같은 기업·연차의 최초 보고서와 다른 경우가 현재 leg **9,710행**,
전년 leg **9,669행**이다. 두 수는 중복될 수 있다. 원래 보고서의 공개일에 나중 접수본 숫자를 붙이지 않았다.
접수번호 차이만으로 모든 raw 값이 정정됐다고 단정하지도 않는다.

**결산 창·숫자:** listing의 `(2024.12)`는 결산 월이지 12개월 기간과 원래 숫자의 증거가 아니다.
원 receipt의 XBRL ZIP이 있을 때에만 실제 Revenue duration, BS instant, issuer, CFS/OFS, KRW 단위,
정확 계정·Decimal 금액을 대조한다. 12달 전체 창과 전년/당년 인접성도 확인한다. 연차 표시를 보고 1/1 시작이나
누락 숫자를 추정하지 않는다. 52/53주·차원/단위 미지원은 차단한다. **이번 고정 원천 집합에는 이 재무 ZIP이
연결되지 않았다.** 선택한 raw commit의 파일 목록에도 원 ZIP 경로는 없었다. 모든 Git 객체나 외부 artifact에
원본이 절대 없다는 주장은 아니다. 따라서 실제 신호값은 전부 `null`로 보존한다.

**기업 신원:** 원 공시의 dated stock code/corpCode와 당해·전년 재무 원천이 일치하고 신호 스냅샷의
회사명도 정확히 맞는 행은 12,425개다. 현재 DART directory, 우선주→보통주, successor, 확인되지 않은
이름 변경으로 메우지 않는다. 영문자가 섞인 KRX 코드도 모집단에서 지우지 않는다.

**산업:** KIND 공지 80건을 보존된 viewer/document 원문에서 재파싱하고 SHA·종목 코드·공개일·효력일을 확인했다.
공개 전·효력 전의 after label과 미래 공지의 before label은 쓰지 않는다. 현재 anchor의 무변경 추정을
역사 PIT라고 부르지 않는다. 공개된 산업 관측은 7,595행, **공지 이전에 공개된** DART 원문으로 그 공지의
issuer를 연결하고 신호일 corpCode까지 맞춘 행은 4,560개다. 80공지 중 이 bridge가 있는 것은 77개다.
이는 **당시 공개된 마지막 공식 관측**이지, 모든 업종 변경을 빠짐없이 확보했다는 인증은 아니다.

**결측·종결·정지:** 미래 종결 사실은 audit-only이며 이전 신호를 차단하는 필터로 쓰지 않았다.
이 기간의 intended 모집단에는 종결 목록 22개 중 10종목이 실제 등장하며 **1,725 member-date**를 모두 보존했다.
나머지 12종목을 이 기간의 Top120에 인위적으로 넣지도 않았다. 마지막 거래일 자체는 생존으로 처리하고,
그 뒤 월간 스냅샷에 남은 **13행**은 ended identity로 차단한다. 거래량 0인 **158행**, 신호일 bar 결측 **13행**도 남긴다.
마지막 가격 청산·정지일 보간·종결 대가 0원 가정은 없다. 신호일의 양의 거래량은 다음 시가 체결이나
보유기간 주주수익을 인증하지 않는다.

## 코드·증거·재현

- `pit_admission.py`: 각 신호일의 intended membership digest, 독립적인 공개일·신원·기간·산업·bar 단계와 비배타 결측 사유.
- `pit_filing_evidence.py`: 원 main 및 원 XBRL의 실제 내용 검사. `verified=true` 같은 외부 주장만 받아 통과시키지 않음.
- `pit_join.py`: 고정 로컬 Git 입력 allowlist만 사용, `GIT_NO_LAZY_FETCH=1`, 가격 shard에서는 신호일 close/volume 상태만 투영.
- `pit_measurement_v1`: 51,360행 metadata와 428개 모집단 영수증, 원천 245개 SHA/크기, 연도별·사유별 집계와 원문 복구 worklist.
- `test_pit_admission.py`: 미래/휴장/누락 snapshot, 부분 모집단, 동일 종목의 다른 날짜, 원 접수번호 불일치,
  원 숫자·기간·단위·기업·차원 오류, 산업 issuer 재사용, 종결·정지·결측, 서버/객체 실패, 영수증 tampering 반례.

```bash
python -m pytest -q research/stock_working_capital_v1
python -m research.stock_working_capital_v1.pit_join                # PLAN_ONLY: 입력 읽기 0
python -m research.stock_working_capital_v1.pit_join --verify research/stock_working_capital_v1/pit_measurement_v1
python -m research.stock_working_capital_v1.pit_join --inspect --output /tmp/wc-pit-new-reproduction
```

마지막 명령의 **exit 3**은 측정은 완료했으나 원천 승인은 BLOCKED라는 뜻이다. 기존 출력 디렉터리는 덮어쓰지 않는다.
Git 객체·원문 hash·서버/프로세스 오류는 exit 4로 실패하며 빈 성공 자료를 만들지 않는다.
원본 read-only 파일의 SHA를 대조하는 검증 외에 기존 봉인 실행기/역사 실험을 실행하지 않는다.

## 다음 최소 작업

`source-demand.json`은 **수익률을 보지 않고** 입력의 다른 조건을 통과한 행에서 필요한 원문을 추렸다.
WC2는 14종목·2,166 member-date에 걸친 **68개 접수번호**, WC1은 5종목·688행에 걸친 **22개**다.
합집합 68개에 원 XBRL URL과 필요한 신호를 기록했지만 다운로드 요청은 하지 않았다.
이는 원천 복구 우선순위이지 14종목 투자 모집단이 아니다. 이 subset으로 최소 표본 기준을 낮추거나
나머지 intended 종목을 빼면 안 된다. 필요한 원문·산업·신원 증거를 확장하고 전체 분모의 회복률을 다시 측정해야 한다.
