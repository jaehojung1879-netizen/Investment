# 전향 기록 설계 — 산업 관찰 목록 v1 (설계만, 미개시)

**원칙**
- 전향 기록 개시는 매매 신호의 승인이 아니다.
- 기존 사전등록 기록(`ledger.yml`이 운영하는 6종)은 건드리지 않는다.
- 이 설계는 사용자 승인(결정 3번) 전까지 실행하지 않는다.

## 1. 기록 대상

| 기록 | 내용 | 주기 |
|---|---|---|
| R1 산업 지표 스냅샷 | 관세청 반도체 수출(10일·20일·월), ECOS D램·플래시 수출물가, 국가데이터처 반도체 생산·출하·재고지수, WSTS, IPG3344S. **원본 응답 바이트 그대로** 저장 | 수집 시점마다(주 1회 + 공표일) |
| R2 미국 산업 BOOM 목록 | #355 S1 정의를 그대로 고정(SIC3, 설비투자×모멘텀 3분위). 판단일·산업·구성 종목·지표값 | 주 1회 |
| R3 반도체 관찰 판단 | 반도체 지표 상태 + 그때의 행동 후보(예: 반도체 바스켓 vs KODEX 200). 행동 후보는 사전등록된 규칙에서만 나온다 | 월 1회 |

## 2. 각 기록의 필수 필드

| 필드 | 설명 |
|---|---|
| `studyId`, `specVersion`, `specSha256` | 사전등록 사양과 버전. 사양 파일은 첫 기록 전에 커밋 |
| `observedAtUtc` | 우리가 실제로 받은 시각(수집기 시계) |
| `sourcePublishedAt` | 원천이 밝힌 공표 시각. 없으면 `null`(추정 금지) |
| `sourceUrl`, `responseSha256`, `responseBytes` | 원본 응답의 해시. 원본은 `signal-history`의 별도 경로에 저장 |
| `revisionOf` | 같은 기간 값을 다시 받았을 때 이전 기록의 해시(개정 추적) |
| `universeAsOf` | 당시 투자 가능 종목군(PIT 구성 스냅샷의 해시) |
| `candidates`, `weights` | 사전등록 규칙이 낸 추천 종목·비중. 규칙이 없으면 빈 값 |
| `benchmark` | 069500(공식 대조 총수익 정의), SPY, QQQ |
| `costModel` | 기존 비용 모듈 버전 |
| `executableAt` | 체결 가능한 첫 세션(공표 시각 기준) |
| `outcome6m`, `outcome12m` | 만기 후 별도 기록. 원 레코드는 수정하지 않는다(append-only) |
| `controls` | 산업·규모·모멘텀 대조군 정의와 결과 |
| `postHocRevisionFlag` | 만기 시점의 원천 값이 기록 시점과 다르면 표시 |

## 3. 판정에 필요한 최소 표본

- **R2(산업 BOOM)**
  - 6개월 결과의 독립 관측은 반년에 하나다. #355의 과거 표준오차(약 0.9%p/6개월)를 그대로 쓰면, 2%p 효과를 80% 검정력으로 보려면 독립 블록 약 16개가 필요하다. 이는 약 8년이다.
  - 따라서 R2는 "판정"이 아니라 과거 탐색 결과의 재현 감시로 운영한다. 3년 시점에 부호만 점검한다.
- **R3(반도체)**: 사이클이 3~5년이라 판정은 사실상 불가능하다. 개정 폭·공표 지연·지표-주가 선후의 기록이 목적이다.
- **R1**: 판정 대상이 아니다. 인프라다.

## 4. 구조(구현은 Codex 작업 D)

- 위치(제안): `signal-history` 브랜치 `ledger/industry-watch/<source>/<YYYY-MM>.jsonl.gz`(append-only). 사양은 `research_specs/industry-watch-v1.json`.
- 수집기는 기존 `pipeline/collector_outcomes.run_outcome` 분류를 쓴다. 거부·빈 응답이 초록색으로 보이지 않게 하는 v2.25 규칙이다.
- 워크플로는 `workflow_dispatch` 전용으로 시작한다. 정기 실행 전환은 사용자 결정이다.
- **ECOS 키(`ECOS_API_KEY`)는 Actions Secret으로만 쓴다.** 이 저장소의 v2.23 기록에 따르면 ECOS 수집 계층은 프로브 외에는 연결되지 않았다.
