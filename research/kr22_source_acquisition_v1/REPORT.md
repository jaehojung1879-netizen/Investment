## 4. 작업 C — 배당결정 141건

`DART_API_KEY`가 있어 실행했다. 공개 CLI의 `collect-remaining`은 **실행 불가 버그**가 있다(`P.collect(plan, out, *callers, ...)`로 호출하지만 `collect`는 `list_page=`, `document=` 키워드 전용이라 `TypeError`). 저장소 파일은 고치지 않고, 같은 함수를 올바른 인자로 호출하는 스크래치 스크립트로 실행했다.

- 141/141 ZIP, 141/141이 `현금ㆍ현물 배당 결정` 서식이고 머리글 날짜가 접수일과 일치했다.
- 기존 `verify-remaining`은 141/141을 **거부**한다. 22건은 ZIP 항목명이 `/`로 시작해 안전 규칙에 걸린다. 나머지 원인은 아래 정정을 보라. 내용 문제가 아니라 검증기 가정 문제이며, 여기서는 고치지 않았다.
  - **정정(2026-10-26, PR #290 `b2d7363`):** 처음에는 "cp949 때문에 발행사 검사가 깨진다"고 적었는데, 틀렸다. `zip_members`는 cp949를 원래 디코딩한다. 실제 원인은 141건 모두 KRX 거래소 공시 서식이라 DART XML 머리글(법인코드)이 없다는 점이다. 수리와 재검증 결과(141/141)는 PR #290의 `kr22-real-data-verification.md`에 있다.
- 발행사 이름이 현재 법인명과 일치: 95건. 46건은 당시 사명이 다르다(LIG손해보험→KB손해보험, 현대증권→KB증권, 쌍용양회공업→쌍용씨앤이, 메리츠종금증권, 현대미포조선, ING생명→오렌지라이프 등). 이 46건의 신원은 법인코드 조회로 보장되며, 이름 일치로는 검증하지 않았다.
- 배당기준일 추출 139건, 지급예정일 추출 73건(추출 한계이지 부재 증명이 아니다).
- **배당락일 표기: 0건.** 141건 어디에도 `배당락`이 없다. 기준일은 배당락일이 아니며, 기준일로 배당락일을 계산하지 않았다.

## 5. 작업 D — 공식 산업분류·배당락일 원천

- **KSIC 코드북:** `kssc.kostat.go.kr`에 연결되지 않아 9차·10차 분류표, 적용 시점, 원문 해시를 확보하지 못했다. 012510의 J58222→582 대응과 042670의 C2924는 **공식 코드북 대조 불가**다.
- 대신 DART `company.json`의 현재 업종코드만 확인했다(시점 정보 없음, 과거 분류 증거가 아님). 012510 → `62022`; 042670 → `29241`. 042670은 공시의 `C2924`와 접두 일치하나 코드북으로 확인한 것이 아니다. 012510의 현재 코드 `62022`는 공시의 `J58222`와 다르다. 분류 체계 개정의 결과일 수 있지만 확인하지 못했다.
- **KRX 결제·배당락 규정:** 포털은 접근된다. 받은 본문은 `유가증권시장 상장규정` 현행본(sha256 `89029d5e…`, 718,155바이트)으로, 결제 주기나 배당락 조항을 담은 업무규정이 아니고 과거 개정 이력도 아니다. 필요한 규정과 시행일별 이력은 아직 취득하지 못했다. 규정 본문 재배포 권한이 확인되지 않아 커밋하지 않았다.
- **KIND 배당락 공지:** 403으로 접근 불가.
- 동결된 연구 규칙은 바꾸지 않았다. 규칙 변경이 필요하면 별도 승인안과 독립 감사, 소유자 승인이 필요하다.
