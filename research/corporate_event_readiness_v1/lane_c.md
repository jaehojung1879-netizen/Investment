# Lane C / empirical metadata inventory

**판정: 원천 일부 확인, 후보 구조 검증 완료, 데이터 적격성 미통과, 실제 경제성 실증 불가.**

고정 #316 `75aab7bc7096b551543bc1582c1e7fd288e94e59`의 254개 발행사 I형 공시 목록을 재사용했다. 신규 DART 호출은 없다. 원문을 이 패킷에 복사하지 않는다. `build_inventory.py`는 임시 추출된 원천의 Git blob ID를 고정 tree와 대조하고 SHA256을 기록한다. 네트워크 fetch는 하지 않는다.

2013-01-01~2026-10-31 I형 제목 부분문자열에 해당하는 **10,615개 공시 버전 / 219개 발행사**를 확인했다. 자본배분 제목 1,941개(직접취득77, 신탁33, 소각541, 처분172, 유증1,089, CB5, EB24), 공급계약 체결 제목8,466개, 해지 제목208개다. 이는 **본문 검증된 사건 수가 아니다**. I형만 보존되어 있으므로 B형 주요사항보고서 전체 건수를 대신하지 않는다. #316의 B형254사 집계와 이 I형 집계를 합산하면 중복 공시 위험이 있다.

정정 제목은4,142/10,615(39.0203%)다. 해지 제목208개 가운데9개는 정정이기도 하며 관계 분류에서 정정을 우선한다. 정정 외 해지는199/10,615(1.8747%)다. 같은 발행사가2회 이상 등장하는 공시의 비중은99.8022%다. 같은 주간 최대 공시는2025-W52의71/10,615(0.6689%)다. 이 집중도는 공시 버전에 관한 기술통계이며 독립 관측치가 아니다. 발행사별·연도별·가족별·주간별 실제 건수는 JSON에 있다. 원문 미파싱은 `NOT_PARSED`, 측정하지 않은 오류율은null로 구별한다. 본 스프린트의 소규모 본문 fixture 파싱 결과는 이 목록 전체를 검증한 것으로 승격하지 않는다.

기존 `top120-inputs.json`의 **164개 월별 스냅샷(2013-01-02~2026-09-01), 매월120종목, 누적260증권**을 직접 집계했다. `strictly prior monthly snapshot` 규칙을 유지한다. 목록의 종목코드와 직전 스냅샷 일치 건수는 참고 진단일 뿐 당시 증권 신원 검증이 아니며 상장/변경/퇴출 날짜를 확정하지 않는다. 원천은 발행사와 증권을 구별해야 하며 하나의 발행사에 여러 증권이 있으면 임의 선택하지 않는다. 회사명 변경으로 신원을 만들지 않고, 변경 당시 코드·유효기간·공개시각과 원문 해시가 필요하다.

고정 `4ea107ed0cde289f0a049a65ff13d2441a786710`의 KRX **2013년 샤드12개월**을 실제 확인했고, 매월300종목·최대rank300으로 잘린 자료다. 나머지13년 샤드는 재확인하지 않았으며 JSON에 미확인 경로를 명시한다. 전체 KOSPI로 이름을 바꿀 수 없다. 원문 KRX 일봉은 전체 단면을 제공할 수 있다는 과거 probe와, 현재 전체기간 원천을 확보했다는 주장은 다르다. 전체 KOSPI 월별 후보 수와 확대 전후 사건 표본의 실제 차이는null이다. 공식 `ACC_TRDVAL`의 과거 trailing window도 이 목록에 없어 유동성 확대 후보 수는null이다. 10억원은 미승인 제안이며 기본값이나 최적화 대상으로 넣지 않았다. `liquidity_candidate`는 외부에서 명시한 제안만 계산하고 항상 연구/수익률 적격성을false로 유지한다. close×volume을 공식 거래대금으로 대체하지 않는다.

기존 종결 인벤토리의22증권을 식별해 코드와 원천 해시만 인계한다. 이는 새 가격·기업행동·종결대가 적격성 승인이 아니다. 월별 목록에서 사라졌다는 사실을 상장폐지 확정으로 읽지 않는다. 원문·기업행동·종결대가·매매가능 가격이 충분하지 않은 증권을 실증 적격으로 승격한 건수는0이다.

PIT 산업 원천, 사건 체인, 정정 링크, 본문 필드, 거래 세션별 정보 가용시각과 H126/H252 공통 적격성 결측이 남아 있다. 따라서 산업 분포는 `UNRESOLVED`, 실제 사건 중첩과 독립N/MDE는null이다. `sample_inventory`는 검증된 calendar와 issuer별 chain이 들어왔을 때만 잠재 중첩을 계산한다. 정정은 별도 독립사건으로 세지 않고, 같은 chain의 복수 원공시는 차단한다. 수익률을 읽지 않고 얻을 수 있는 이 입력을 먼저 채워야 Opus가 사전등록을 확정할 수 있다.

재현: 모듈 docstring의 두 `git archive` 명령(두번째는 `ledger/universe/kr/krx-universe-2013.jsonl.gz` 단일 경로)으로 임시 디렉터리에 고정 원천을 추출한 뒤 `python -m research.corporate_event_readiness_v1.build_inventory --source-root /tmp/investment-lane-c --output /tmp/inventory.json`을 실행한다. 새 JSON과 보존 JSON의 byte 일치를 확인한다. 이는 기존 목록의 재집계이며 Atlas/Phase C/C2 재실행이 아니다.

Top120 파생 패킷과 종결 인벤토리는 baseline main `37f8cbf6b1c066f6b3c65235953648d17ebf2f69`의 exact SHA256을 코드에서 강제한다. 로컬 파일이 바뀌면 새 숫자로 조용히 갱신하지 않고 실패한다.
