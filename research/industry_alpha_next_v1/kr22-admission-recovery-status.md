**새로 확보한 원천: 0건.** DART, KRX, KIND, 법령 호스트가 모두 CONNECT 403으로 막혀 있고 `DART_API_KEY`도 없다. 반복 요청이나 우회는 하지 않았다.

## 2. 종결 공시 35건 (Priority 2)

**정확한 목록:** `kr22-terminal-viewer-plan.json`(digest `9711552e…`, 35건, `kr22_terminal_viewer.py plan`으로 재현).

- 모두 `document.xml`이 014(파일 미제공)로 응답한 접수이다.
  - 27건은 `[기재정정]`, 7건은 `[첨부정정]`이다.
  - 나머지 1건은 금융감독원 정정명령부과(012510)다.
- 원본 결정 공시는 이미 보존돼 있다(92건). 35건은 그 **정정본**이다.
- 저장소의 기존 실패 검토(`docs/results/kr-terminal-document-parsing.json`)가 매긴 분류를 그대로 실었다.
  - MATERIALLY_BLOCKING 20: 000030, 000830, 002550, 003450, 003600, 010520, 037620, 079440.
  - POTENTIALLY_MATERIAL 10.
  - REDUNDANT 5.

**정정(이전 보고 철회):** 000060, 008560, 057050의 신주 수가 "35건에 들어 있을 것"이라고 한 것은 틀렸다.

- 세 종목의 결정 공시는 모두 이미 SUCCESS로 받았다. 35건에는 이 세 종목이 하나도 없다.
- 신주 수는 다른 종류의 공시(발행 실적이나 종료 보고 계열)에 있을 것이다.
- 정확한 보고서명은 승계 회사에 대한 `list.json` 조회로 확인해야 한다. 추정해 요청 목록에 넣지 않았다.

**재사용:** 새 HTTP 코드나 파서는 만들지 않았다.

- HTTP는 기존 공개 뷰어 수집기를 그대로 쓴다. `scripts/collect_kr_industry_membership_sources.Collector.request`(호출 예산, 본문 크기 제한, 키 불필요)와 `nodes()`이다. 그 파일은 수정하지 않았다.
- 기존 `receipt()`는 사업보고서 두 절만 받는다. 그래서 새 모듈은 접수의 **모든 노드**를 접수당 최대 15개까지 받는다.
- 파싱은 92건 원본에서 검증된 `pipeline.kr_terminal_action_document_parser`를 그대로 쓴다. 정정전/정정후 표는 자동 표시되고, 결정 조건 행으로 읽지 않는다.

**검증 항목(오프라인):**
- 아카이브와 객체의 SHA;
- 계획 digest;
- `openCorpInfoNew('<corp>',` 고유성(발행사 식별);
- 제목의 접수일과 정정 표시;
- 노드의 rcpNo가 해당 접수인지.

**추출(후보만, 채택 없음):**
- 정정전/정정후 행;
- 합병비율, 교환비율;
- 합병기일, 주식교환일, 이전일;
- 신주 수, 현금 교부액;
- 양도기준일.

**수집 실패와 원본 부재를 구분한다.**
- 전송 실패, HTTP 오류, 크기·예산 초과는 실패로만 기록한다.
- 같은 전송 실패가 3번 연속되면 멈춘다.
- 35건은 모두 저장소 공시 색인(list.json)에 이미 나온다. 그래서 뷰어가 비어도 "원본 없음"으로 판정하지 않고 `LISTED_BUT_VIEWER_EMPTY`로 남긴다. 사람이 읽고 판단한다.

**승인된 환경에서 실행:** 모드 A. Allowed domains에 `dart.fss.or.kr`를 추가하며, 키는 필요 없다. 호출은 최대 560회(35 × (1 + 15))이다.

```
# 0) 한 번만 확인. 403/000이면 멈춘다(반복 요청 금지).
curl -sS -o /dev/null -w "%{http_code}\n" --max-time 15 "https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20181121000025"
# 1) 수집 (출력 디렉터리는 없어야 함)
python -m research.industry_alpha_next_v1.kr22_terminal_viewer collect --output <빈 디렉터리>
# 2) 오프라인 검증 + 후보 추출 (네트워크 없음)
python -m research.industry_alpha_next_v1.kr22_terminal_viewer verify --input <디렉터리> > terminal-viewer-verification.json
```

**결과의 쓰임:**
- `VERIFIED` 접수의 정정후 값은 기존 `data/kr-terminal-document-review.json`의 사람 검토 절차로만 `data/kr-terminal-corporate-actions.json`에 들어간다.
- 이 모듈은 아무것도 채택하지 않는다.

## 3. 산업 후보 (Priority 1)

상세는 `industry-admission-rule-proposal.md`이고, 숫자는 `kr22-table-ksic-candidates.json`이다.

- **왜 놓쳤나:** v2 템플릿은 발행사 주어 문장과 배정 동사를 요구한다. 012510은 제목 줄과 계층표로 적었다. 크로스워크는 3자리(KIND) 라벨인데, 012510이 보고한 라벨은 5자리다.
- **J58222 ↔ 582:** 공시 자신의 계층표 J / 58 / 582 / 5822 / 58222가 보고 코드의 접두와 모두 일치한다(8/8).
  - 공식 코드북과는 대조하지 못했다. 저장소에 코드북이 없다.
- **대칭 적용:** 254개 발행사의 2,786건 전체에 같은 규칙을 적용했다.
  - 표 형식 진술: 012510 한 곳(8건)뿐이다.
  - 계열회사 표 자사 행: 31개 발행사, 163행. KIND 라벨과 일치하는 행은 7/144(4.9%)이고, 크로스워크에 정확히 있는 10행 중 3행은 KIND 그룹과 다르다. 그래서 거절을 권고한다.
- **식별·시점 보존:** 접수번호, `known_from` = 접수일, corp code, 공시 자신의 법정 명칭을 기록했다. 현재 DART 회사명은 쓰지 않았다.
